# Proactive trigger strength and optional research-scope regression cases

## Test status and burden of proof (2026-10-12)
- **Contract/static tests**: `python -m unittest discover -s tests -p test_trigger_scope_strength.py -v` checks a pinned repository checkout. A PASS verifies text/section placement only, **not a behavioral PASS**.
- **Behavioral replay**: all T01–T20 remain **NOT RUN / E2E UNKNOWN** until a separate live ChatGPT project run with pinned installed rules, actual tool calls, research W-ID, outputs and decisions. Do not infer behavior from a checklist.
- Core 4 independent axes: (a) important assessment **triggers without user request** (b) real evidence search/verification (c) valuable individual candidate visibility plus elective user choice (d) bounded execution and closure.
- “High trigger” does NOT mean a mandatory user pause, exhaustive source search, minimum candidate count, or automatic investigation of newly discovered optional axes.
- For behavioral PASS inspect exactly which sources were opened, what contradictions or alternatives were sought, which candidate axes were proposed, user authorization, the W-ID actual updates, the next step and whether unapproved branches were untouched.

## Recording an actual replay
For each case note scenario fixture, pinned code and actually injected rules (UNKNOWN if unavailable), tool calls and actual pages/lines read, A–E classification, value-ranked discovered candidates and hidden/filtered candidates, bundled routes, user decision, changes actually made, repeated rounds, and decision about ending. Mark **PASS / FAIL / UNKNOWN / NOT RUN** per axis, not a single unspecified overall score.

A high-value omitted candidate should be grounded as far as feasible **before presenting it** (targeted provisional source confirmation), but a successful proposal does not itself authorize a full new W-ID. No fixed number of candidate ideas or rounds. Separate existing-work evidence errors from optional out-of-plan expansions.
